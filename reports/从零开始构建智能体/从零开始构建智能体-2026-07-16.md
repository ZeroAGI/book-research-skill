## 🎯 为什么要读这本书

### 它解决什么问题？

2025 年被公认为「Agent 元年」：技术焦点从训练更大的基础模型转向构建更聪明的智能体应用。Gartner 将 Agentic AI 列为 2025 年顶级技术趋势第一名，全球 AI Agent 市场规模预计从 2024 年的 51 亿美元增至 2030 年的 471 亿美元（CAGR 44.8%）。[来源](https://blog.csdn.net/Guo_Python/article/details/162202950)

然而，市场上存在三大痛点：

1. **框架文档碎片化**：AutoGen/LangGraph 各说各话，学习者不知道该学哪个、能构建什么
2. **系统性教程匮乏**：要么是纯理论，要么是纯框架调用，缺少从原理到实现的完整路径
3. **「用轮子」与「造轮子」脱节**：会用 LangChain 但不懂它为什么这样设计，遇到问题无从下手

Hello-Agents 正是为填补这一空白而生——它提供了一条从概念到代码、从单 Agent 到多 Agent 系统的系统学习路径。[来源](https://zhuanlan.zhihu.com/p/1965351417196836801)

### 目标读者是谁？

🟢 **最适合的读者**：有 Python 基础（能写函数、会调用 API）但对 Agent 开发缺乏系统认知的开发者。最理想的读者画像是——会 Python、用过 ChatGPT API、想知道 Agent 到底是怎么回事，但被 LangChain 文档和 AutoGen 各说各话搞糊涂了的人。

### 分章详解

#### 第一部分：智能体与语言模型基础（第 1-3 章）

**第 1 章：初识智能体**

核心论点：智能体是能够通过传感器感知环境、通过执行器自主行动以实现目标的实体。LLM 的出现彻底改变了智能体的构建范式——从工程师显式编程转向模型内隐的世界知识与涌现能力。

关键概念：
- **PEAS 任务环境模型**（感知/执行/环境/传感器）——来自经典教材《人工智能：现代方法》（Russell & Norvig），用于系统分析任意 Agent 系统的设计需求
- **传统五类智能体进化阶梯**：简单反射 → 模型反射 → 目标 → 效用 → 学习
- **Workflow vs Agent 本质区别**：Workflow 预先定义所有步骤；Agent 能基于实时信息动态推理和决策
- **神经符号 AI 类比**：LLM 提供「系统 1」（快速直觉），结构化推理步骤提供「系统 2」（慢速逻辑）——对应卡尼曼《思考，快与慢》双系统理论

贯穿案例：智能旅行助手作为全书示例项目的起点。

**第 2 章：智能体的发展历史**

核心论点：智能体的历史是从符号主义到连接主义、再到 LLM 驱动的三次范式转变。理解这段历史有助于避免重蹈覆辙，正确认识当前 Agent 热潮的技术根基与局限。

关键时间线：专家系统（知识瓶颈）→ 强化学习崛起 → ReAct（2022）→ AutoGPT（2023）→ MCP（2024）→ Agent 元年（2025）

**第 3 章：大语言模型基础**

核心论点：LLM 是智能体的「大脑」。理解 Transformer 架构、条件概率、提示工程等底层原理，是构建可靠智能体的必要地基。

关键概念：
- Transformer 自注意力架构（Google, 2017）
- Decoder-Only 架构与「预测下一个 token」统一训练目标
- N-gram 语言模型与条件概率
- 主流 LLM 的优劣对比（GPT 系列、DeepSeek-V3 等）
- LLM 的幻觉问题——这是智能体系统设计需要规避的核心挑战

#### 第二部分：构建你的大语言模型智能体（第 4-7 章）

**第 4 章：经典智能体范式构建（ReAct / Plan-and-Solve / Reflection）** ★ 全书最受好评章节

核心论点：三种经典范式各司其职，互补而非竞争——社区总结的口诀是：「边想边做用 ReAct，想好再做用 Plan-and-Solve，做好再反思用 Reflection」。从零实现比使用框架更能理解原理。[来源](https://www.cnblogs.com/yisheng163/p/19205821)

**ReAct（Reason + Act）**：
- 最基础的 Agent 循环，由姚顺宇等于 2022 年提出（发表于 ICLR 2023）
- 核心结构：Thought（推理分析）→ Action（工具调用）→ Observation（工具返回结果），循环直到任务完成
- 适用场景：需要外部工具的探索性任务
- 示例：查询华为最新手机型号（调用 SerpApi 搜索工具）
- 局限：强依赖 LLM 格式遵循能力、串行调用延迟高、局部最优风险

**Plan-and-Solve（规划后执行）**：
- 由王磊等于 2023 年提出，显式解耦规划与执行
- 两阶段架构：规划阶段生成完整 n 步计划 → 执行阶段按步骤顺序执行
- 适用场景：确定性的多步推理（数学/逻辑/报告写作）
- 示例：解决水果店多日销量数学题（4 步规划 → 依次执行）
- 类比：若 ReAct 是「经验丰富的侦探循线索追查」，Plan-and-Solve 是「建筑师先画完整蓝图再施工」

**Reflection（执行 → 反思 → 优化）**：
- 灵感来自 Shinn 等人 2023 年的 Reflexion 工作（NeurIPS 2023）
- 三步循环：执行初稿 → 独立 LLM 扮演「极严苛代码评审专家」评估 → 结合反馈优化
- 适用场景：高质量要求的任务（代码生成、科学推理）
- 示例：将 O(n√n) 试除法自动优化为 O(n log log n) 埃拉托色尼筛法
- 成本收益：每轮至少 2 次额外 LLM 调用，以成本换质量

**第 5 章：基于低代码平台的智能体搭建**

核心论点：低代码平台让非程序员快速构建 Agent 应用，但其本质是「知其然不知其所以然」。低代码是入门，代码实现才是精通。

三大平台对比：
- **Coze（字节跳动）**：零代码快速发布，适合一键发布多平台
- **Dify（开源）**：8000+ 插件、企业级、MCP 支持，适合复杂场景
- **n8n**：可视化工作流节点，适合工作流自动化集成

**第 6 章：主流智能体框架开发实践**

核心论点：掌握多框架有助于根据场景选型。社区总结的选型建议 [来源](https://www.cnblogs.com/yisheng163/p/19205821)：

| 框架 | 特点 | 最佳场景 |
|------|------|----------|
| AutoGen | 对话驱动多智能体协作 | 多 Agent 代码审查流程 |
| AgentScope（阿里） | 工程优先、生产级 | 企业级 Agent 部署 |
| CAMEL | 角色扮演范式与引导提示 | 创新交互场景 |
| LangGraph | 状态图控制流（含 human-in-the-loop） | 需要精确控制流的复杂任务 |

**第 7 章：从零构建 HelloAgents 框架** ★ 核心差异化章节

核心论点：「除了核心 Agent 类，一切皆工具」是 HelloAgents 的核心设计哲学。基于 OpenAI 原生 API 从零构建，消除不必要抽象层，让学习者真正理解每个组件的作用。

关键设计：
- **「一切皆工具」统一抽象**：记忆、RAG、RL、MCP、搜索引擎等均统一为「工具」
- **三层架构**：核心层（core/）+ Agent 实现层（agents/）+ 工具系统层（tools/）
- **五类 Agent 实现**：SimpleAgent / ReActAgent / ReflectionAgent / PlanAndSolveAgent / FunctionCallAgent
- **多提供商自动检测**：通过环境变量 → 域名解析 → API 密钥格式的优先级链自动适配 OpenAI/ModelScope/Ollama
- **ToolRegistry 服务定位器模式**：统一工具接口为「字典输入 → 字符串输出」

渐进式学习路径：每章代码可独立安装运行，避免全局依赖冲突。

#### 第三部分：高级知识扩展（第 8-12 章）

**第 8 章：记忆与检索（Memory & RAG）**

核心论点：智能体的记忆系统是其「延伸感官」。在 HelloAgents 框架中，MemoryTool 和 RAGTool 均以「工具」形态统一管理。

关键概念：
- 四种记忆类型与整合机制（MemoryTool）
- RAG（检索增强生成）原理与实现——解决 LLM 上下文窗口有限的核心问题
- 向量数据库与语义检索
- MQE（多查询扩展）和 HyDE（假设文档嵌入）高级搜索策略

**第 9 章：上下文工程**

核心论点：上下文工程是智能体持续交互的命脉。如何在有限的上下文窗口中有效管理信息流，是决定智能体表现的关键工程挑战之一。

关键实现：ContextBuilder 的 GSSC 流水线，优化上下文构建效率。

**第 10 章：智能体通信协议（MCP / A2A / ANP）** ★ 前沿内容亮点

核心论点：三个协议分别解决不同层次的互联互通问题：

| 协议 | 提出者 | 解决什么问题 | 类比 |
|------|--------|-------------|------|
| MCP（Model Context Protocol） | Anthropic, 2024 | Agent 与工具/数据源的连接标准化 | USB-C 统一充电接口 |
| A2A（Agent-to-Agent Protocol） | - | 智能体之间点对点协作 | 两人对话 |
| ANP（Agent Network Protocol） | - | 大规模智能体网络的互联互通 | 社交网络 |

与 Agent Skills 的区别：MCP 解决「连接」问题，Skills 提供「操作手册」（如何使用工具的程序性知识）。

社区扩展章节 Extra-05 的深度分析 [来源](https://github.com/datawhalechina/hello-agents/blob/main/Extra-Chapter/Extra05-AgentSkills%E8%A7%A3%E8%AF%BB.md)：
- Token 效率量化：Playwright MCP eager-loading 消耗 200k 上下文窗口的 8%；Skills 渐进式加载将初始负载降至约 100 tokens/skill
- 三层架构：Metadata（~100 tokens）→ Instructions（1-5k tokens）→ Resources（按需加载）

**第 11 章：Agentic 强化学习（从 SFT 到 GRPO）** ★ 稀缺前沿内容

核心论点：Agentic RL 是 2025 年最前沿的方向，让智能体通过反复实践自我纠错和优化。这是「普通教程都不敢碰」的硬核内容。

完整训练流水线：
1. **SFT（监督微调）**：用高质量示范数据建立行为基线
2. **GRPO（组相对策略优化）**：模型生成多个候选输出，通过奖励信号对比组内相对质量进行优化

这是 OpenAI o1/o3 等推理模型背后核心技术的简化教学版，代表了从「使用 LLM」到「训练专用 Agent 模型」的技术跃迁。

**第 12 章：智能体性能评估**

核心论点：没有评估就没有改进。掌握权威基准和评估框架是系统性提升智能体性能的科学方法。

关键基准：
- BFCL（Berkeley Function Calling Leaderboard）：评估工具调用准确率
- GAIA：评估通用 AI 助手能力

#### 第四部分：综合案例进阶（第 13-15 章）

**第 13 章：智能旅行助手**

核心论点：综合运用 MCP 协议 + 多 Agent 协作，构建真实可用的旅行规划系统。

技术栈：Vue3 + TypeScript 前端集成，体现「分工明确、接口标准化」的多智能体工程原则。

**第 14 章：自动化深度研究智能体（DeepResearch 复现）** ★ 实用落地案例

核心论点：TODO 驱动研究范式将复杂研究任务分解为「规划 → 执行 → 整合」三阶段流水线。

三 Agent 串行协作：
1. **TODO Planner**：将主题分解为 3-5 个子任务（含 title/intent/query 的 JSON）
2. **Task Summarizer**：搜索 + 提取核心观点 + 带编号引用的结构化 Markdown
3. **Report Writer**：整合所有摘要，消除重复，统一引用格式

工程亮点：MD5 哈希缓存、多搜索引擎降级容错（Tavily/SerpApi/DuckDuckGo/Perplexity/SearXNG）、SSE 实时流式前端、ToolAwareSimpleAgent 工具监听器。

## 💡 关键洞见

### 1. AI 原生 Agent vs 软件工程 Agent：两条技术路线的本质区别 🟢

当前 Agent 开发分为两大流派：以 Dify、Coze、n8n 为代表的「软件工程型 Agent」，本质是以 LLM 为数据处理后端的流程驱动开发；以及「AI 原生 Agent」，真正由 AI 驱动、能自主推理决策的智能体。两者的核心区别在于：Workflow 预先定义所有步骤；Agent 能基于实时信息动态推理和决策。

**为什么重要**：这一判断帮助读者在众多工具和框架中找到方向，避免将低代码平台的工作流自动化误认为是真正的 AI Agent 开发。在 2025 年 Agent 元年的背景下，理解这一区分是选择学习路径和技术栈的前提。

**如何应用**：如果你的应用场景是固定流程的自动化（如客服问答、数据处理），低代码平台足够；如果需要动态推理、不确定性环境中的自主决策，则需要构建 AI 原生 Agent。

### 2. 三大核心组件：规划 + 工具调用 + 记忆反思 🟢

任何 LLM 驱动的智能体都由三个核心组件构成：（1）规划模块——ReAct、Chain-of-Thought、树搜索等推理范式；（2）工具调用接口——基于 JSON Schema 的函数调用；（3）记忆与反思机制——向量数据库、自我改进循环。

**为什么重要**：这三个组件形成完整的「感知 → 推理 → 行动 → 反馈」闭环，是理解和设计任意 Agent 系统的统一分析框架。无论使用何种框架，都可以从这三个维度解构其架构。

**如何应用**：评估任何 Agent 框架时，检查它在这三个维度上的支持程度——哪个规划范式？工具调用如何实现？记忆如何管理？这三个问题的答案决定了框架的适用场景和局限。

### 3. ReAct：几乎所有现代 Agent 框架的默认架构 🟢

ReAct 将思维链推理（CoT）与工具调用行动交织进行，核心洞见是：「纯思考」无法与外部环境交互、易产生幻觉；「纯行动」缺乏规划和纠错。ReAct 将两者结合，是 Agent 开发的「Hello World」。

**为什么重要**：理解 ReAct 是理解所有更复杂 Agent 架构的前提。书中提供了完整的从零实现代码，包括 prompt 模板、正则解析、工具注册系统——这些是框架黑箱中隐藏的核心逻辑。

**如何应用**：任何新的 Agent 项目都应该先用 ReAct 作为基线实现，验证任务可行性后再考虑更复杂的范式。正则解析 Thought/Action 输出格式是最常见的工程细节——工具描述的质量直接决定 LLM 何时调用哪个工具。

### 4. 「一切皆工具」：从复杂到简单的核心简化 🟢

HelloAgents 框架的核心设计哲学：除了核心 Agent 类，所有模块统一抽象为「工具」，消除不必要的抽象层。工具接口统一为「字典输入 → 字符串输出」，通过 ToolRegistry 服务定位器模式管理。

**为什么重要**：这一哲学解释了为什么从零构建框架比使用现成框架更有教育价值——它揭示了所有复杂框架背后的统一抽象逻辑。学完 HelloAgents 再看 LangGraph，才知其所以然。

**如何应用**：在设计自己的 Agent 系统时，先问「这个模块能不能抽象为工具？」——如果能，就用统一的工具接口，保持架构简洁。但要注意，这种简化在教学中有效，在生产环境中需要补充错误恢复、token 效率、渐进式加载等工程细节。

### 5. 三种范式的互补关系：选型决策指南 🟢

「边想边做用 ReAct，想好再做用 Plan-and-Solve，做好再反思用 Reflection」——这不是竞争关系而是互补关系，实际工程中往往混合使用。

**为什么重要**：Reflection 是「以成本换质量」的策略，每轮至少 2 次额外 LLM 调用，最适合高精度需求（关键业务代码、科学推理、决策支持系统）。Plan-and-Solve 适合需要架构规划的确定性多步任务。ReAct 适合灵活探索。选错范式会导致成本浪费或质量不足。

**如何应用**：面对新任务时，按照这个决策树选型：需要实时外部工具 → ReAct；确定性多步推理 → Plan-and-Solve；高质量要求且不急于响应 → Reflection。复杂系统可能在不同环节使用不同范式。

### 6. MCP/A2A/ANP：Agent 生态的基础设施革命 🟡

MCP 解决 Agent 与工具的「连接」标准化（类比 USB-C），A2A 解决 Agent 间点对点协作，ANP 解决大规模 Agent 网络互联。这三个协议是 Agent 生态互联互通的关键基础设施。

**为什么重要**：2024-2025 年 Agent 生态中最重要的基础设施发展。没有标准化协议，每个 Agent 系统都是孤岛；有了协议，Agent 就像互联网中的节点，可以发现彼此并协作。本书是国内最早系统讲解 MCP 全栈应用的教程之一。

**如何应用**：新项目优先使用 MCP 协议连接外部工具，而非自定义 API 包装。多 Agent 协作场景考虑 A2A 通信格式。关注这三个协议的演进，它们将定义 Agent 开发的未来标准。

### 7. Agentic RL：从「使用 LLM」到「训练专用 Agent 模型」的跃迁 🟡

通过强化学习让智能体自我进化：SFT 建立行为基线 → GRPO 通过反复实践自我纠错和优化。这是 OpenAI o1 等推理模型背后的核心技术。

**为什么重要**：代表了 Agent 能力的最前沿——不再依赖通用 LLM 的能力上限，而是针对特定任务训练专用 Agent 模型。这是其他中文 Agent 教程鲜有涉及的内容。

**如何应用**：当通用 LLM + 提示工程无法满足特定任务需求时，考虑 Agentic RL 微调。但需要注意计算资源成本和训练数据质量要求。

### 8. TODO 驱动研究范式：将复杂任务工程化 🟡

将「研究」分解为多个子任务（TODOs），逐一执行后整合结果。三阶段架构：规划（分解子任务）→ 执行（搜索+摘要+持久化）→ 报告（整合+消除重复+统一引用）。

**为什么重要**：解决了信息过载、碎片化和重复劳动三大研究痛点。每个 Agent 简单、易维护，体现单一职责原则——这是将 Agent 技术落地为实用工具的典型范例。

**如何应用**：任何需要多步信息收集和整合的任务都可以借鉴这一范式。关键工程细节：MD5 缓存避免重复搜索、token 限制（约 2000 tokens/源）控制成本、多搜索引擎降级容错保证可用性。

### 9. 神经符号 AI：理解 LLM Agent 的认知科学视角 🔴

LLM Agent 是神经符号 AI 的现代实现——神经网络核心提供「系统 1」（快速直觉/模式识别），结构化的中间推理步骤提供「系统 2」（慢速逻辑推理）。Agent 产生的 thoughts/plans/API calls 既是「显式的、可操作的符号」，又依托神经网络的强大模式识别能力。

**为什么重要**：将 AI 理论史、认知科学和工程实践三个领域贯通，提供了理解 LLM Agent 深层本质的思维框架。

**如何应用**：设计 Agent 系统时，有意识地区分哪些部分依赖「系统 1」（LLM 直觉判断），哪些部分需要「系统 2」（显式规划、工具调用、约束检查），并为后者提供足够的结构化支持。

### 10. 「用轮子」到「造轮子」的渐进式教育哲学 🟢

先用低代码平台看见效果 → 再用现成框架提升效率 → 最后从零构建自己的框架——「兼具用轮子与造轮子的能力」。

**为什么重要**：解决了 Agent 学习的核心矛盾：框架让上手容易但理解肤浅；从零构建理解深刻但门槛高。分阶段学习兼顾了两者。

**如何应用**：学习新框架时，先用它跑通一个简单案例（用轮子），然后尝试不用框架、仅用原生 API 复现同样功能（造轮子）。两个版本的代码对比是最有效的学习方法。

## 🔍 批判性分析

### 优势

1. **学习路径设计精准** 🟢：「概念 → 范式 → 低代码 → 主流框架 → 自建框架 → 高级主题 → 综合案例 → 毕业设计」的 16 章线性递进结构被知乎评价为「顺序是对的」，这是区别于碎片化框架文档的最大优势 [来源](https://zhuanlan.zhihu.com/p/2055717433445557614)

2. **从零实现的教学深度** 🟢：三大经典范式均提供完整的从 OpenAI 原生 API 出发的代码实现，而非封装调用，真正帮助学习者理解 Agent 循环的每个环节 [来源](https://blog.csdn.net/Chen__2024/article/details/160957355)

3. **前沿话题覆盖广度** 🟡：Agentic RL（SFT → GRPO）、MCP/A2A/ANP 协议栈、上下文工程等内容在同类中文教程中极为稀缺 [来源](https://blog.csdn.net/Guo_Python/article/details/162202950)

4. **免费开源且持续更新** 🟢：CC BY-NC-SA 4.0 协议完全免费，三种阅读形式（在线/GitHub/PDF），828 次提交持续迭代

5. **综合案例的工程完整性** 🟡：三个毕业级项目均包含前后端完整实现，不是简单的 notebook 演示而是可部署的应用

6. **社区生态丰富** 🟢：13 篇社区扩展章节、14 天组队学习计划、配套视频教程、Agent-Learning-Hub 资源库形成完整学习生态

7. **诚实的局限性披露** 🟢：教程自身坦诚讨论 LLM 的幻觉、无状态性和计算局限，被多方评价为严谨性的体现

### 不足

1. **文档与代码不同步** 🟢：GitHub 72 个 open issues 中多涉及初始化顺序错误、不存在的 memory key、qdrant-client 版本冲突等基础问题，新手往往因此卡壳 [来源](https://github.com/datawhalechina/hello-agents/issues)

2. **教学级框架与生产需求的鸿沟** 🟢：HelloAgents 框架缺乏企业级高并发、高可用、多租户、错误恢复等能力，学习者从教程到实际工作存在显著知识跳跃

3. **仅限 Python 单一技术栈** 🟡：对 JavaScript/TypeScript/Java/Go 等技术栈的开发者参考价值有限

4. **国际化不足** 🟡：内容几乎全为中文，英文版网站存在已知 bug [来源](https://dev.to/wonderlab/one-open-source-project-a-day-61-hello-agents-a-practical-guide-to-building-ai-native-agents-224k)

5. **宣传材料存在自我膨胀倾向** 🟡：「全网最系统」「AI Agent 黄埔军校」等表述缺乏客观方法论支撑

6. **时效性风险突出** 🟡：AI Agent 领域月度演进速度极快，2025 年编写的内容在细节层面可能已部分过时

7. **开源模型适配有限** 🟡：框架优先支持 OpenAI API 格式，对 Ollama 本地部署、国产开源模型的兼容性测试不充分

8. **缺乏标准化测评反馈机制** 🟡：虽有习题设计，但缺乏自动化测试或在线评判系统来验证学习者代码实现

### 核心矛盾分析 ★

本次研究发现了五个值得关注的矛盾：

**矛盾 1：「从零开始」的承诺 vs 实际前置门槛**

书名「从零开始构建智能体」暗示零基础友好，README 也宣称帮助学习者「从 LLM 使用者蜕变为智能体系统构建者」。然而，多位读者反馈第 4 章纯代码实现对零编程基础者有明确门槛，条件概率符号需要查阅外部资源理解。知乎评价明确指出「如果完全没有编程基础，这套教程可能会有点陡」。[来源](https://zhuanlan.zhihu.com/p/2055717433445557614)

> **分析**：「从零开始」实际指从 Agent 知识零基础开始，而非编程零基础。这一命名可能误导部分目标受众。教程的真实前置条件是：基础 Python + LLM API 调用经验。

**矛盾 2：「全网最系统」的自我定位 vs 实际覆盖局限**

CSDN 宣传文将 Hello-Agents 定位为「全网最系统的 Agent 教程」，与 LangChain 文档、吴恩达课程对比声称六维度优势。但知乎客观评价指出：框架缺乏企业级能力、内置工具数量远少于 LangChain、对开源模型适配有限。

> **分析**：「最系统」在学习路径的完整性和顺序合理性上成立，但在工程深度、生态广度和语言覆盖上不成立。核心价值在于「正确的学习顺序」而非「最全面的知识覆盖」。

**矛盾 3：「一切皆工具」的教学价值 vs 工程实用性**

作者团队高度强调「一切皆工具」是理解 Agent 架构的核心抽象。但社区扩展章节分析了 MCP eager-loading 消耗 8% 上下文窗口的问题，暗示纯「工具」抽象在复杂场景下的 token 效率挑战。

> **分析**：「一切皆工具」作为教学简化原则是优秀的——它让初学者快速建立正确心智模型。但这一简化恰恰是它无法直接用于生产的原因：真实系统需要渐进式加载、更精细的上下文管理、错误恢复等工程细节。

**矛盾 4：GitHub Star 数作为质量指标的可靠性**

66,500+ Stars 被多方引用为教程质量的最直接证据。但 72 个 open issues 涉及文档与代码不同步、运行报错等基础质量问题。高 Star 数可能部分反映 Datawhale 社区的组织化推广能力（覆盖 2000+ 院校）。

> **分析**：Star 数反映了「市场需求 + 社区推广 + 内容质量」的综合结果，不能等同于纯质量指标。它更准确地反映了中文 Agent 教程市场的巨大供需缺口。

**矛盾 5：覆盖低代码平台的必要性 vs 核心定位矛盾**

书籍在第 5 章系统介绍低代码平台（Coze/Dify/n8n），但核心框架中明确区分「软件工程类 Agent」和「AI 原生 Agent」，认为前者不是真正的 Agent。

> **分析**：这是一个有意为之的教学设计选择——先展示低代码平台是为了让学习者理解其局限性，从而更好地理解为什么需要从代码层面构建。但可能让部分非技术读者误以为教程适合他们。
